PART 1 — Fix Request to Join behavior

Problem:
Host-approval Moves should not behave like instant-join Moves.

Expected behavior:

For normal Moves:
- CTA says “I’m In”
- tapping opens Save your spot modal
- confirming joins the Move
- going count increases
- spots left decreases
- Move Chat appears
- notification added:
  “Your spot is saved for [Move Name].”

For host-approval Moves:
- CTA says “Request to Join”
- tapping does NOT add the user immediately
- going count does NOT increase
- spots left does NOT decrease
- Move Chat does NOT appear while pending
- save request status in mock localStorage
- button changes to “Request Sent”
- show toast:
  “Request sent. The host will review it.”
- add notification:
  “Request sent for [Move Name].”

Suggested localStorage key:
`brio_join_requests`

Suggested request object:
- id
- moveId
- moveName
- requesterName
- status: pending
- createdAt

Important distinction:
- “I’m In” = instant join
- “Request to Join” = asks host for approval
- “Ask Host” = asks a question, not a join request

PART 4 — Improve safety/reporting logic

Pre-Move safety should be softer and should not be framed like a full post-Move report.

Pre-Move action:
“Something feels off”

When tapped, open modal/sheet:

Title:
“Something feels off?”

Subtitle:
“Tell us what’s making you unsure. We’ll use this to review the Move.”

Options:
- Move details seem misleading
- Location feels unsafe
- Host feels suspicious
- Spam or scam
- I’m uncomfortable with this Move
- Other

After selecting an option, show text area:

Label:
“Add a few details”

Placeholder:
“What happened or what feels off?”

Buttons:
- Cancel
- Send for Review

After submitting:
- show toast:
  “Thanks. We’ll review this.”
- add notification:
  “Your safety note was sent for review.”

Do not publicly display the safety note.
Do not immediately penalize anyone from this pre-Move flow.

Post-Move reporting should be stronger and only appear in After the Move / post-Move context.

Post-Move report title:
“Report this Move”

Subtitle:
“Tell us what happened. Reports are private.”

Post-Move options:
- Host didn’t show
- Attendee didn’t show
- Made me uncomfortable
- Harassment
- Fake Move
- Unsafe situation
- Spam / scam
- Other

After choosing an option, show text area:

Label:
“Add details”

Placeholder:
“What happened?”

Buttons:
- Cancel
- Submit Report

After submitting:
- show toast:
  “Thanks. We’ll review this.”
- add notification:
  “Your report was submitted for review.”

Suggested localStorage key:
`brio_safety_reports`

Suggested object:
- id
- moveId
- moveName
- reportContext: preMove or postMove
- reportType
- details
- createdAt
- status: submitted
