docs/02_PRODUCT_SPEC.md

Include:

Brielo Product Spec

Product Summary

Brielo is a mobile social lifestyle app that helps people make real-life Moves, meet people through activities, and add good people to their Circle.

Brielo is not:

* a dating app
* a professional networking app
* just an event listing app
* just a nightlife app
* a recurring club app by default

Core Insight

People do not just need more events. They need help turning social intent into real-life action and finding people they would actually do things with again.

Product Language

* Moves = one-time activities users create or join
* Make a Move = create an activity
* Make It Live = submit/create a Move
* I’m In = join a Move
* Leave Move = leave a Move and remove its chat
* Move Chat = temporary chat for a joined Move
* Circle = people the user has moved with and would move with again
* Add to Circle = add someone after a Move
* In Your Circle = already added
* Circle Activity = updates from people the user has moved with before
* Live Moves Nearby = active nearby Moves
* Live Map = map view of nearby Moves
* After the Move? = post-Move reactions, feedback, Would Move Again, and Add to Circle
* Sessions = structured activities like gym, study, work, gaming, creative, or skill-based meetups
* Brielo Livestreams = future feature only, not MVP core

Important Circle Clarification

Circles are people-based, not recurring themed groups by default.

A Circle is a lightweight social graph made from people the user met through Moves and would move with again.

Do not treat Circles as:

* recurring clubs by default
* themed community groups by default
* Meetup-style groups by default
* Crews

Current MVP Screens

* Onboarding / Welcome
* Interest Selection
* Discover / What’s the Move?
* Live Moves Nearby
* Make a Move
* Move Detail
* Move Chat list
* Move Chat detail
* Leave Move flow
* Live Map
* Profile
* Activity History
* Your Circle / Circle Activity
* After the Move?
* Safety / Reporting
* Theme Settings

Current Prototype Status

* Built in Replit
* Mobile-first React/Tailwind-style prototype
* Uses localStorage/mock data
* Buttons are clickable
* Posting a Move works
* Created Moves appear in the app
* No real backend yet
* No real authentication
* No payments
* No WebSockets
* No push notifications
* No real livestreaming
* No production database yet

docs/05_DECISION_LOG.md

Include:

Brielo Decision Log

Locked Product Decisions

1. App name is Brielo.
2. Pronunciation is BREE-loh.
3. Primary tagline is Live More.
4. Main action phrase is Make a Move.
5. Moves are one-time activities.
6. The create submit CTA is Make It Live.
7. The join CTA is I’m In.
8. Move Chat is temporary and tied to a joined Move.
9. Leave Move should remove the user from the Move and remove the Move Chat from the chat list.
10. Circles are people-based social connections, not recurring themed groups by default.
11. Add to Circle means adding someone you moved with and would move with again.
12. Circle Activity means updates from people you’ve moved with before.
13. Do not use Crew/Crews language.
14. Do not use Plan/Plans language.
15. Do not use Rally/Rallies language.
16. Do not use Brio as the current user-facing app name.
17. Use clean line icons, not native emoji icons.
18. Logo is wordmark-first with a small yellow custom dot over the “i.”
19. Do not use checkered flags, racing visuals, sun icons, spark icons, or heavy lightning/bolt branding.
20. Brielo Livestreams is future/later-stage only, not MVP core.
21. Current prototype should remain localStorage/mock data until backend is intentionally added.
22. Do not add backend, WebSockets, real auth, payments, or livestreaming without explicit approval.

Trust/Reputation Direction To Add Later

Brielo should eventually penalize flaking fairly.

Principle:
When a user taps “I’m In,” they are holding a limited spot that someone else may have wanted.

Future trust/reputation ideas:

* show-up rate
* recently missed Moves
* Would Move Again count
* Good Vibes count
* host reliability
* private safety/report signals
* warning labels like Low Show-Up Rate or Recently Missed Moves
* avoid public shaming or harsh labels like “flake” or “bad user”
* allow reputation recovery through consistent attendance

Do not implement this yet unless specifically requested.
