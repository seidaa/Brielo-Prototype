PART 1 — Polish “Save your spot?” modal copy

Problem:
The current copy says something like:

“Tapping I’m In holds a spot someone else may want — only join if you plan to show.”

This feels a little awkward.

Update the modal copy to be more natural, clear, and firm.

Preferred copy:

Title:
“Save your spot?”

Body:
“Only 3 spots left for Leg Day at XSport.”

Secondary body:
“Only join if you plan to show. When you save a spot, someone else may miss out.”

Primary button:
“I’m In — Save My Spot”

Secondary button:
“Not yet”

Footer copy:
“Things come up. Leaving before it starts opens your spot back up and does not count as a no-show.”

Keep the spot count and Move name dynamic.

Make sure this copy still works if the Move has a different number of spots or different title.

PART 2 — Make notifications update from prototype actions

Problem:
The notification drawer currently opens, but posting, joining, leaving, and canceling Moves do not update the notification list. This makes the notification menu feel static.

Expected behavior:
Use localStorage/mock state to add lightweight notifications when key prototype actions happen.

Add a simple notification system if one does not already exist.

Suggested localStorage key:
`brio_notifications`

Add notifications for these actions:

1. When the user joins a Move:
   “Your spot is saved for [Move Name].”

2. When the user leaves a Move:
   “You left [Move Name]. Your spot is open again.”

3. When the user creates/posts a Move:
   “Your Move is live: [Move Name].”

4. When the host cancels a Move:
   “[Move Name] was canceled. The chat is closed.”

5. When post-Move feedback is submitted:
   “Thanks for your feedback on [Move Name].”

Keep notifications lightweight and prototype-friendly.

Notification drawer behavior:

* show newest notifications first
* show timestamp-style text if easy, like “now” or “2m ago”
* the red notification dot should appear when there are unread notifications
* opening the notification drawer can mark notifications as read and clear the red dot
* if there are no notifications, show:
  “You’re all caught up.”

Do not create real push notifications.
Do not request notification permissions.
Do not add backend notification logic.
